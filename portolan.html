The Portolan catalogs used

Sovereignty isn't a wall. It's controlling every layer — storage, engine, AI, platform, governance — while staying fully interoperable with the world.

04

Portolan as living infrastructure

A registry isn't just read — agents and publishers can improve it. Three ideas we're exploring (mock-ups; toggle them):

IDEA 01

Self-registration & telemetry — opt-in

An agent can register (anonymously) so publishers learn which datasets and regions are actually queried — and prioritise what to convert next. Always opt-in; the user stays in control.

Share anonymous usage telemetry
Off · nothing leaves your session.
IDEA 02

Agents contribute their prompts

The query the agent wrote to target the data is itself signal. Contributing it (opt-in) helps publishers understand real use cases — what people actually ask of their data.

last query targeted:
nls.v2.power_lines · ST_Distance
“nearest transmission line to a data-centre site”
IDEA 03

Issues, data requests & PRs

Each catalog exposes a git repo. Missing a dataset? Found bad metadata? Want a layer converted? Open an issue, request data, submit a use case, or send a pull request — the catalog is governed in the open.
